## 二、逐项整改

### 4.1 密码信息泄露【重度】— 已修复

**问题**：`/api/n9e/datasource/list` 返回包中携带数据源的明文凭据（口令、密钥、证书等）。

**根因**：该接口对**管理员角色**豁免了脱敏，导致任一持有管理员令牌者（或在页面存在 XSS 时）可经此接口一次性拉取全部数据源的后端连接凭据。

**整改**：取消管理员豁免，接口对**所有角色无条件脱敏**（口令/密钥/证书/认证头/加密配置等敏感字段统一清空），与平台其它数据源读取接口（`/datasource/brief`）行为一致。

**影响评估**：平台前端的数据源编辑流程读取走 `/datasource/brief`（本就脱敏）、保存走独立的 upsert 接口，均**不依赖** `/datasource/list`，故本次脱敏不影响任何业务功能。

**验证**：以管理员身份请求 `/api/n9e/datasource/list`，返回包中敏感字段为空/掩码。

---

### 4.2 开启 HTTP 危险方法【中度】— 已修复

**问题**：服务器响应 `TRACE` 等非常规 HTTP 方法；报告同时指出 `DELETE` 方法可用。

**整改**：在 nginx 443 入口封禁 `TRACE`、`TRACK` 方法（返回 405）——这两类是跨站追踪（XST）、窃取 Cookie/认证头的真实攻击向量。

**关于 `PUT`/`DELETE` 的说明**：本平台 nginx 为**全量反向代理**至后端应用 n9e，**不提供任何文件系统写入/WebDAV 能力**。平台 `PUT`/`DELETE` 是应用层 RESTful 资源操作（如删除告警规则、删除数据源、更新配置），由后端应用在**账号鉴权 + 权限校验**之后执行，不等同于「上传/删除服务器文件」。若在 nginx 层强行禁用 `PUT`/`DELETE`，将导致平台管理功能不可用。因此保留 `GET/POST/PUT/DELETE/HEAD/OPTIONS`，仅封禁 `TRACE/TRACK`。

**验证**：
- `TRACE https://10.77.80.193/` → `405`
- `TRACK https://10.77.80.193/` → `405`
- 正常业务 `GET`/`POST`/`DELETE`（经鉴权）不受影响。

---

### 4.3 HTTP Host 头攻击【中度】— 已修复

**问题**：`/api/n9e/assistant/voice` 接口会将客户端传入的 `Host` 头反映到生成的链接中，攻击者篡改 `Host` 可诱导用户访问恶意地址。

**根因**：该语音接口的反代配置使用 `proxy_set_header Host $http_host`，将**客户端原始 Host 原样透传**给后端。

**整改**：平台语音功能当前不投入使用，直接在 nginx 封禁该接口（返回 403），从被演示的攻击点根除 Host 透传。将来若启用语音功能，将改用可信的服务端域名（`SERVER_NAME`）而非客户端 `Host` 后再放开。

**验证**：
- `GET https://10.77.80.193/api/n9e/assistant/voice` → `403`
- `GET https://10.77.80.193/api/n9e/assistant/voice/ws` → `403`
- 平台其它页面/接口正常（首页 `200`、受保护 API 未授权 `401`）。

---

### 4.4 系统功能未完善【中度】— 说明

报告列出的「删除功能异常/部分功能报错/用户锁定机制」等属**功能完整性**问题，非安全配置项，不涉及 nginx/网关层整改，由平台产品/功能迭代处理或按需关闭对应模块。其中「用户锁定机制」为**预期的账号安全特性**（多次登录失败锁定），非缺陷。
