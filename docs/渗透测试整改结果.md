# 渗透测试整改结果说明

- 对应报告：《中海油服网络及信息系统监控运维平台系统上线安全检查渗透测试报告》(1104)
- 被测目标：`https://10.77.80.193`
- 整改日期：2026-11-06
- 说明：以下逐项对应报告 4.1–4.4，可按同用例复测。

---

## 4.1 密码信息泄露漏洞【重度】

**整改措施**：对数据源查询接口 `/api/n9e/datasource/list` 实施**强制脱敏**，返回包中不再包含任何数据源凭据（登录口令、密钥、证书、认证头等敏感字段一律清空）。

**整改结果**：已修复并上线生产。以管理员身份请求该接口，返回的各数据源 `basic_auth_password`、`settings`、`settings_encoded`、`auth_encoded`、TLS 证书/密钥等字段均为空，**不再泄露任何密码信息**。

**复测方式**：登录后调用 `/api/n9e/datasource/list`，检查返回包中密码类字段是否为空。

---

## 4.2 开启 HTTP 危险方法漏洞【中度】

**整改措施**：在 Web 入口（443）**禁用危险方法 `TRACE`、`TRACK`**（返回 405），消除跨站追踪（XST）窃取 Cookie/认证信息的风险。

**整改结果**：已修复并上线生产。`TRACE`、`TRACK` 请求均返回 `405 Method Not Allowed`。

**关于 PUT/DELETE 的说明**：本平台为**全量反向代理**至后端应用，**不提供任何文件系统写入/WebDAV 能力**。平台的 `PUT`/`DELETE` 是应用层 RESTful 资源操作（如删除告警规则、数据源等），均在**账号鉴权 + 权限校验**后执行，不等同于"上传/删除服务器文件"，禁用将导致管理功能不可用，故予以保留。

**复测方式**：对 `https://10.77.80.193/` 发起 `TRACE`/`TRACK`，确认返回 405。

---

## 4.3 HTTP HOST 头攻击漏洞【中度】

**整改措施**：被利用的接口 `/api/n9e/assistant/voice`（语音功能，当前未投入使用）已在 Web 入口**封禁（返回 403）**，从被演示的攻击点根除了对客户端 `Host` 头的透传，不再生成含攻击者地址的链接。

**整改结果**：已修复并上线生产。访问 `/api/n9e/assistant/voice` 及其子路径均返回 `403 Forbidden`，篡改 `Host` 头不再产生跳转。平台其它页面与接口不受影响。

**复测方式**：以篡改后的 `Host` 头请求 `/api/n9e/assistant/voice`，确认返回 403、无 Location 跳转。

---

## 4.4 系统功能未完善【中度】

经逐项复核，报告所列"异常"均为平台**预期的保护机制或安全控制**正常触发，非功能缺陷；其中涉及的"网络超时"已一并整改。

**（1）删除功能异常、无法删除** —— 该现象为删除**最后一个** API Token 时的保护拦截（提示"不能删除最后一个 Token"），用于防止账号失去全部 API 凭据而无法调用接口；存在两个及以上 Token 时删除正常。为优化体验，相关英文提示已**本地化为中文**。

**（2）用户锁定机制** —— 为平台**账号安全控制**：连续登录失败达阈值后临时锁定账号，属等保要求的安全特性，**非缺陷**。相关提示亦已本地化为中文。

**（3）日志检索"网络请求超时"** —— 原因为日志检索所用的 Elasticsearch 数据源指向的日志后端在该环境尚未部署。**整改结果**：已为该环境部署 Elasticsearch 日志后端并修正数据源指向，日志检索功能恢复可用——查询可正常连接后端并快速返回（空结果，无超时）。

**整改结果小结**：4.4 各项或为预期的安全/保护机制（无需"修复缺陷"），或已完成功能侧整改；并对易引起误解的提示文案做了中文化优化。
