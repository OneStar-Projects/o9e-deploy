## 二、渗透整改逐项

### 4.1 数据源明文凭据泄露【重度】
- **问题**：`/api/n9e/datasource/list` 回传数据源明文凭据（口令/密钥/证书/认证头）。生产分支（sync）原仅对非管理员脱敏、**管理员被豁免**；main 分支更早、**完全不脱敏**。
- **改动**：
  - sync 分支（生产）：去掉 `if !user.IsAdmin()`，改**无条件 `RedactSecrets()`**。commit `6c265b2f`。
  - main 分支（保留）：老版无 RedactSecrets，改为 `ClearPlaintext()` + 清 SettingsEncoded/AuthEncoded/HTTP TLS·Headers。commit `c119d328`。
- **零回归依据**：前端（生产/测试同哈希 bundle）对 `/datasource/list` **零引用**，编辑读走 `/datasource/brief`（本就脱敏）、存走 upsert，不依赖本接口。
- **验证**：admin 登录后 `POST /datasource/list` → ES-1/VM-1 的 basic_auth_password、settings、settings_encoded、auth_encoded、TLS 字段**全部为空**。

### 4.2 开启 HTTP 危险方法【中度】
- **改动**：443 server 加 `if ($request_method ~* ^(TRACE|TRACK)$) { return 405; }`。
- **说明**：报告建议只留 GET/POST，但 PUT/DELETE 是 n9e 应用层 RESTful 资源操作（经鉴权），非文件操作，封了废功能，故仅封 XST 向量 TRACE/TRACK。
- **验证**：TRACE/TRACK→405；GET→200；PUT/DELETE 业务正常。

### 4.3 HTTP Host 头攻击【中度】
- **问题**：`/api/n9e/assistant/voice` 的 location 用 `proxy_set_header Host $http_host`，把客户端（攻击者）Host 透传给后端，生成含恶意 Host 的链接。
- **改动**：语音功能当前不用 → `location ^~ /api/n9e/assistant/voice { return 403; }`，并删除随之孤儿的 `map $o9e_voice_connection`。
- **验证**：`/assistant/voice` 及子路径→403；首页/其它 API 正常。将来恢复语音须改用 SERVER_NAME 再放开。

### 4.4 系统功能未完善【中度】— 无真缺陷
逐一复核报告截图，均为**预期保护/安全控制**，非缺陷：
- "删除功能异常无法删除" = 删最后一个 API Token 返回 `cannot delete the last token`（`router_self.go` 保护：`tokenCount<=1` 拦截）。
- "部分功能异常报错" / "用户锁定机制" = 登录失败锁定 `reach login fail count`（`models/user.go`，等保要求的安全特性）。
- **体验优化**：这两条英文提示原因是 i18nx 全局 zh_CN 字典缺 key 而回落英文。已补两条中文翻译（`i18nx/var.go`，commit `65a8ac1b`），不改任何安全逻辑。

## 三、网络超时（报告 4.4 的"网络请求超时"）

- **根因**：日志检索用 **ES-1** 数据源，原 urls=`http://elasticsearch:9200`（docker 网名），而**生产 ecs1 未部署 ES** → 点查询连不上 → 超时。非安全问题，是功能可用性。
- **处置（ES 放 ecs2，因 ecs1 内存紧 ~1.7Gi）**：
  - ecs2 起 ES：`elasticsearch:8.15.3` 单机 + basic auth + 堆 1g + **发布 `192.170.19.27:9200`** + 卷 `o9e-es-data` + restart=always；`discovery.type=single-node` 跳过 bootstrap 检查（免 sudo 改 max_map_count）、`node.store.allow_mmap=false`。
  - 镜像来源：ecs1 本地已有 ES 镜像，内网直传 ecs1→ecs2。
  - ES-1 数据源（id=2）经 admin API upsert 改指：urls→`192.170.19.27:9200`、basic_auth=true、user=elastic、新口令（本地 `~/.config/n9e/es_ecs2_pw`）。
- **验证**：`POST /api/n9e/indices {cate:elasticsearch,datasource_id:2}` → 200 / 0.25s / 空索引，**不再超时**。
- **现状**：ES 空库无日志数据；要真有日志需再接 logstash/采集链路（未做）。
